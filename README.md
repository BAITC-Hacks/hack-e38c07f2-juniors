# AlemQuest

**Платформа практических задач для бизнеса и студенческих команд.**

Проект команды **Juniors** для хакатона **HackAlem AI**.

## О проекте

AlemQuest помогает бизнесу превратить краткое описание проблемы в понятную задачу для студентов: уточнить требования, указать доступные данные, определить ожидаемый результат и критерии успеха.

Студенческие команды просматривают открытый каталог, выбирают интересные задачи и предлагают решения. Бизнес самостоятельно рассматривает предложения и выбирает исполнителей.

Главная механика геймификации направлена на бизнес: **чем полнее описание задачи и больше подтверждённых сведений, тем выше рейтинг готовности и позиция в каталоге**.

## Что реализовано

### Конструктор бизнес-задачи

- Ввод названия, отрасли и свободного описания.
- Получение 3–5 уточняющих вопросов.
- Перенос ответов в редактируемую карточку.
- Подтверждение каждого поля человеком.
- Сохранение без публикации или размещение в общем каталоге.
- Редактирование ранее созданной задачи.

Карточка содержит контекст, потребность, данные, ожидаемый результат, критерии успеха, ограничения, пользователей, контакт и формат взаимодействия.

### Рейтинг готовности

- Оценка от 0 до 100.
- Расшифровка начисленных баллов.
- Пересчёт в интерфейсе при заполнении и подтверждении полей.
- Независимый расчёт на сервере при сохранении.
- Подсказки о недостающих сведениях.

### Каталог и предложения

- Общий каталог опубликованных задач.
- Сортировка по рейтингу.
- Поиск по названию, компании и описанию.
- Фильтры по отрасли и уровню готовности.
- Отклик команды с идеей, планом, сроком и ссылкой на прототип.
- Просмотр предложений в кабинете бизнеса.
- Ручное принятие и отклонение предложений.
- Возможность выбрать несколько команд.

### Прогресс команд

После подтверждения бизнесом завершённого этапа выбранная команда получает 10 баллов. Повторное подтверждение того же этапа не увеличивает результат.

### AI-помощник

Встроенный чат открывается кнопкой в правом нижнем углу. Он помогает уточнить задачу, объясняет рейтинг, публикацию и работу с предложениями.

Помощник использует OpenAI API. Отдельная интеграция с Chatbase не требуется.

### Языки и оформление

- Русский, казахский и английский интерфейс: RU / KZ / EN.
- Три темы: **Петроль**, **Слива**, **Терракота**.
- Сохранение выбранного языка и темы в браузере.
- Сохранение введённых данных при переключении языка.

Пользовательские тексты задач и ответов автоматически не переводятся.

## Как работает решение

1. Представитель бизнеса вводит описание проблемы.
2. Система предлагает уточняющие вопросы.
3. Пользователь отвечает и переносит сведения в карточку.
4. Бизнес проверяет и подтверждает заполненные поля.
5. Рейтинг отражает готовность задачи к работе.
6. После отдельного подтверждения публикации карточка появляется в каталоге.
7. Студенческая команда выбирает задачу и отправляет предложение.
8. Бизнес рассматривает отклики и вручную выбирает одну, несколько или ни одной команды.
9. После выполнения этапа бизнес подтверждает результат, и команда получает баллы.

В MVP нет отдельных аккаунтов: сценарии бизнеса и студентов доступны через общее меню.

## Формула рейтинга

```text
Рейтинг = сумма весов заполненных и подтверждённых полей
```

Поле учитывается, если содержит минимум 5 символов после удаления пробелов по краям и подтверждено пользователем.

| Показатель | Баллы |
|---|---:|
| Контекст | 10 |
| Потребность | 10 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт | 5 |
| Формат взаимодействия | 5 |
| **Всего** | **100** |

### Уровни готовности

| Баллы | Уровень |
|---|---|
| 0–39 | Черновик |
| 40–69 | Рабочая |
| 70–89 | Готовая |
| 90–100 | Приоритетная |

Изменение текста в интерфейсе снимает подтверждение соответствующего поля.

Рейтинг проверяет заполненность и подтверждение сведений. Он не является автоматической проверкой достоверности или смыслового качества текста.

## Правила каталога

- Все опубликованные задачи доступны всем командам.
- Низкий рейтинг не скрывает задачу и не запрещает отклики.
- Неопубликованные карточки отображаются в кабинете бизнеса.
- Уровень готовности «Черновик» не означает, что задача не опубликована.
- Число откликов программно не ограничивается.
- Выбор одной команды не отклоняет другие предложения автоматически.
- AI не назначает исполнителей и не принимает решения за бизнес.

|---|---|

## Архитектура

```text
Браузер
  ├── Каталог и конструктор
  ├── Кабинет бизнеса и команды
  ├── Переключатели языка и темы
  └── AI-чат
          |
          | HTTP / JSON
          v
      Node.js сервер
          ├── Валидация запросов
          ├── Расчёт рейтинга
          ├── Сохранение данных
          └── OpenAI API / локальные ответы
```

Данные сохраняются в `data/db.json`. Запись выполняется через временный файл и переименование. Настройки интерфейса сохраняются в `localStorage`.

### Основные маршруты API

| Метод и путь | Назначение |
|---|---|
| `GET /api/state` | Получение задач, рейтингов, команд и откликов |
| `POST /api/analyze` | Уточняющие вопросы |
| `POST /api/assistant` | Ответ встроенного AI-помощника |
| `POST /api/tasks` | Создание, редактирование и публикация задачи |
| `POST /api/proposals` | Отправка предложения |
| `POST /api/proposals/:id` | Решение бизнеса или подтверждение этапа |

## Установка и запуск

Требуется **Node.js 22.9 или новее**.

### 1. Клонировать репозиторий

```bash
git clone https://github.com/BAITC-Hacks/hack-e38c07f2-juniors.git
cd hack-e38c07f2-juniors
```

### 2. Запустить без внешнего AI

```bash
node server.js
```

Открыть:

```text
http://localhost:3000
```

При первом запуске автоматически создаётся хранилище с демонстрационными данными. Задачи, отклики и решения сохраняются после перезапуска.

Без API-ключа доступны локальные вопросы и резервные ответы помощника.

### 3. Подключить OpenAI

Создать `.env` на основе `.env.example` и указать настройки:

```dotenv
PORT=3000
OPENAI_API_KEY=your_api_key_here
OPENAI_MODEL=gpt-4.1-mini
```

Остановить ранее запущенный сервер через `Ctrl+C`, затем выполнить:

```bash
node --env-file=.env server.js
```

Альтернативная команда при наличии npm:

```bash
npm start
```

Ключ используется только сервером. Файл `.env` исключён из Git и не должен публиковаться.

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `PORT` | Порт сервера, по умолчанию `3000` |
| `OPENAI_API_KEY` | Ключ OpenAI API |
| `OPENAI_MODEL` | Модель, по умолчанию `gpt-4.1-mini` |
| `DATA_DIR` | Каталог хранения данных, по умолчанию `data/` |

Индикатор «AI настроен» означает наличие ключа в конфигурации. Успешность соединения проверяется реальным запросом.

## Как используется AI

### Уточняющие вопросы

Сервер передаёт описание и заполненные поля модели. Промпт требует вернуть от 3 до 5 вопросов, не добавлять неизвестных фактов и не выбирать исполнителей.

Пример ответа:

```json
{
  "questions": [
    {
      "field": "data",
      "question": "Какие данные о продажах доступны команде?"
    },
    {
      "field": "success",
      "question": "Как вы будете оценивать точность прогноза?"
    },
    {
      "field": "constraints",
      "question": "К какому сроку нужен первый прототип?"
    }
  ]
}
```

Сервер проверяет структуру ответа, допустимые и уникальные ключи, количество вопросов и длину текста.

Ответы пользователя переносятся в карточку буквально. Перед публикацией сведения подтверждает человек.

### Диалоговый помощник

Для ответа используются последние 12 сообщений диалога. Каждое сообщение ограничено 2000 символами.

Помощник:

- отвечает на выбранном языке интерфейса;
- задаёт вопросы для уточнения задачи;
- объясняет возможности платформы;
- не публикует карточки и не изменяет решения бизнеса;
- не получает автоматически содержимое задач из хранилища.

История чата хранится в памяти страницы и сбрасывается после обновления.

### Обработка ошибок

При отсутствии ключа, недоступности API, таймауте или некорректном ответе используются локальные вопросы либо резервный ответ чата. Пользователь видит соответствующее сообщение.

Локальный режим не является вызовом AI-модели.

## Как проверить решение

### Автоматические тесты

```bash
node --test
```

Проверяются:

- границы уровней готовности;
- начисление баллов за подтверждённые поля;
- валидация AI-ответов;
- публикация задачи;
- отклик на задачу с нулевым рейтингом;
- ручной выбор команды;
- подтверждение этапа без повторного начисления баллов;
- сохранность данных после перезапуска;
- ограничения истории чата;
- локальные ответы на выбранном языке;
- наличие переводов интерфейса.

Тесты используют отдельное временное хранилище и не требуют API-ключа.

### Сценарий для жюри

1. Открыть «Создать задачу» и нажать «Подставить пример».
2. Получить уточняющие вопросы.
3. Ответить минимум на три вопроса и перенести ответы в карточку.
4. Подтвердить контекст, потребность и данные — рейтинг станет **40/100**.
5. Заполнить и подтвердить остальные поля — рейтинг станет **100/100**.
6. Подтвердить публикацию и найти задачу в каталоге.
7. Отправить предложение от команды: идею, план, срок и ссылку на прототип.
8. В кабинете бизнеса открыть предложения и выбрать команду.
9. Для демонстрации завершённого этапа подтвердить его и проверить начисление **10 баллов**.
10. Обновить страницу и убедиться, что данные сохранились.

Подготовленные ответы и план выступления находятся в [DEMO.md](DEMO.md).

### Проверка дополнительных функций

- Переключить RU / KZ / EN и проверить меню, формы и фильтры.
- Ввести текст в форму и сменить язык — текст должен сохраниться.
- Выбрать другую тему и обновить страницу — выбор должен сохраниться.
- Открыть AI-помощника и спросить, как повысить рейтинг.
- Проверить, что опубликованная задача с низким рейтингом принимает предложения.

## Данные и интеграции

Начальный набор в `lib/seed.js` содержит:

- 5 исходных описаний задач;
- 5 карточек разной готовности;
- 5 профилей команд;
- 5 предложений.

Данные синтетические. Контакты используют домен `.example`, ссылки на прототипы — демонстрационные адреса `example.com`.

Внешние сервисы:

- **OpenAI API** — уточняющие вопросы и диалоговый помощник.
- **Google Fonts** — загрузка шрифта Manrope.

При подключённом API-ключе введённые данные для анализа и сообщения помощнику отправляются OpenAI. NVIDIA API и Chatbase в текущей версии не используются.

## Ограничения текущей версии

- Нет регистрации, авторизации и разграничения доступа.
- Все демонстрационные роли доступны из общего интерфейса.
- Достоверность и смысловое качество описания подтверждает человек.
- Один подтверждаемый этап на отклик.
- Нет чата между бизнесом и командами, уведомлений и файлового хранилища.
- Нет персональных рекомендаций и автоматического назначения команд.
- Тексты задач не переводятся автоматически.
- История AI-чата не сохраняется после обновления страницы.
- JSON-хранилище рассчитано на один серверный процесс.
- Сервер слушает `127.0.0.1` и предназначен для локальной демонстрации.
- Работа внешнего AI зависит от доступности API, ключа и выбранной модели.
