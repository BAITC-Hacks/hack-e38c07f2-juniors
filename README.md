# AlemQuest

**Платформа практических задач для бизнеса и студенческих команд.**

Проект команды **Juniors** для хакатона **HackAlem AI**.

AlemQuest помогает бизнесу превратить краткое описание проблемы в понятную карточку задачи. Студенческие команды просматривают открытый каталог, выбирают интересные проекты и предлагают решения.

Главная механика геймификации: чем полнее бизнес описал и подтвердил задачу, тем выше её рейтинг и позиция в каталоге.

## Проблема

Студентам сложно начать работу с задачей, если неизвестны доступные данные, ожидаемый результат, ограничения и критерии успеха.

AlemQuest помогает уточнить эти сведения до начала сотрудничества и делает готовность задачи прозрачной для обеих сторон.

## Что реализовано

### Для бизнеса

- Создание задачи из свободного описания.
- Получение 3–5 уточняющих вопросов.
- Перенос ответов в редактируемую карточку.
- Подтверждение заполненных полей.
- Рейтинг готовности от 0 до 100 с расшифровкой.
- Публикация задачи в общем каталоге.
- Просмотр и сравнение предложений команд.
- Ручной выбор или отклонение предложений.
- Подтверждение завершённого этапа работы.

### Для студентов

- Просмотр всех опубликованных задач.
- Поиск и фильтрация по отрасли и уровню готовности.
- Просмотр требований и недостающих сведений.
- Отправка идеи решения, плана, срока и ссылки на прототип.
- Получение баллов за этап, подтверждённый бизнесом.

В MVP используется демонстрационный режим без регистрации: оба сценария доступны через общее меню.

## Как работает платформа

1. Бизнес вводит название, отрасль и описание проблемы.
2. Система задаёт уточняющие вопросы.
3. Пользователь отвечает и переносит ответы в карточку.
4. Бизнес проверяет сведения и подтверждает поля.
5. Рейтинг пересчитывается по мере заполнения.
6. После подтверждения публикации задача появляется в каталоге.
7. Команда самостоятельно отправляет предложение.
8. Бизнес вручную выбирает одну, несколько или ни одной команды.
9. После подтверждения выполненного этапа команда получает 10 баллов.

Повторное подтверждение одного этапа не увеличивает баллы.

## Геймификация и рейтинг

Рейтинг отражает готовность конкретной задачи к работе.

```text
Рейтинг = сумма весов заполненных и подтверждённых полей
```

Поле учитывается, если содержит минимум 5 символов после удаления пробелов по краям и подтверждено пользователем. Изменение текста в интерфейсе снимает подтверждение поля.

| Показатель | Баллы |
|---|---:|
| Контекст | 10 |
| Потребность | 10 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт | 5 |
| Формат взаимодействия | 5 |
| **Всего** | **100** |

### Уровни готовности

| Рейтинг | Уровень |
|---|---|
| 0–39 | Черновик |
| 40–69 | Рабочая |
| 70–89 | Готовая |
| 90–100 | Приоритетная |

Рейтинг вычисляется на сервере. Он проверяет заполненность и подтверждение полей, но не достоверность фактов или смысловое качество текста.

## Правила каталога

- Все опубликованные задачи доступны всем командам.
- Задачи сортируются по убыванию рейтинга.
- Низкий рейтинг не скрывает задачу и не запрещает отклик.
- Неопубликованный черновик доступен в кабинете бизнеса.
- Число откликов программно не ограничивается.
- Выбор одной команды не отклоняет остальные предложения автоматически.
- AI не назначает исполнителей и не принимает решение за бизнес.

## Использование AI

AI анализирует описание и заполненные поля, затем предлагает уточняющие вопросы.

Интеграция использует OpenAI Chat Completions API. Модель по умолчанию — `gpt-4.1-mini`, её можно изменить через переменную окружения.

Промпт находится в `lib/domain.js`. Он требует:

- задавать от 3 до 5 вопросов;
- использовать русский язык;
- возвращать структурированный JSON;
- не добавлять неизвестные факты;
- не выбирать команду за бизнес.

Пример ответа:

```json
{
  "questions": [
    {
      "field": "data",
      "question": "Какие данные доступны для работы команды?"
    },
    {
      "field": "success",
      "question": "Как вы будете оценивать успешность решения?"
    },
    {
      "field": "constraints",
      "question": "К какому сроку нужен первый прототип?"
    }
  ]
}
```

Сервер проверяет структуру, количество вопросов, допустимые ключи и длину текста.

При отсутствии ключа, ошибке API, таймауте или некорректном ответе используются локальные вопросы по незаполненным полям. Интерфейс сообщает о резервном режиме. Локальная генерация не является вызовом AI-модели.

Ответы пользователя переносятся в карточку буквально и подтверждаются человеком.

## Технологии

- **Frontend:** HTML, CSS, JavaScript.
- **Backend:** Node.js, встроенный модуль `node:http`.
- **Хранение:** локальный JSON-файл.
- **AI:** OpenAI API через серверный `fetch`.
- **Тестирование:** `node:test`, `node:assert/strict`.
- **Оформление:** Manrope через Google Fonts, запасной Arial.

Сторонние npm-зависимости и сборка не требуются.

## Установка и запуск

Требуется **Node.js 22.9 или новее**.

```bash
git clone https://github.com/BAITC-Hacks/hack-e38c07f2-juniors.git
cd hack-e38c07f2-juniors
node server.js
```

Откройте:

```text
http://localhost:3000
```

При первом запуске создаётся `data/db.json` с демонстрационными данными. Изменения сохраняются после перезапуска сервера.

### Подключение OpenAI

Создайте `.env` на основе `.env.example`:

```dotenv
PORT=3000
OPENAI_API_KEY=your_api_key_here
OPENAI_MODEL=gpt-4.1-mini
```

Остановите сервер и запустите с настройками:

```bash
node --env-file=.env server.js
```

При наличии npm можно использовать:

```bash
npm start
```

Ключ используется только на сервере. Файл `.env` исключён из Git.

Индикатор «AI подключён» означает наличие ключа в конфигурации. Для проверки реального соединения запросите уточняющие вопросы и убедитесь, что приложение не перешло в локальный режим.

## Проверка решения

### Автоматические тесты

```bash
node --test
```

Проверяются:

- границы уровней готовности;
- начисление баллов за подтверждённые поля;
- обработка некорректных ответов AI;
- публикация задачи;
- отклик на задачу с нулевым рейтингом;
- ручной выбор команды;
- подтверждение этапа;
- сохранение данных после перезапуска.

Тесты используют отдельное временное хранилище и не требуют API-ключа.

### Сценарий для жюри

1. Открыть «Создать задачу» и подставить пример.
2. Получить уточняющие вопросы.
3. Ответить на них и перенести ответы в карточку.
4. Подтвердить контекст, потребность и данные — рейтинг станет 40.
5. Заполнить и подтвердить остальные поля — рейтинг станет 100.
6. Подтвердить публикацию и найти задачу в каталоге.
7. Отправить предложение от команды.
8. В кабинете бизнеса выбрать эту команду.
9. Подтвердить этап и проверить начисление 10 баллов.
10. Обновить страницу и убедиться, что данные сохранились.

Подробный сценарий защиты находится в [DEMO.md](DEMO.md).

Начальный набор содержит:

- 5 карточек разной готовности;

## Ограничения MVP

- Нет регистрации, авторизации и разграничения доступа.
- Качество и достоверность сведений подтверждает человек.
- Один подтверждаемый этап на отклик.
- Нет чата, уведомлений, загрузки файлов и персональных рекомендаций.
- JSON-хранилище рассчитано на один серверный процесс.
- Реальный AI-вызов требует действующего ключа и доступа к модели.
- Сервер предназначен для локальной демонстрации и слушает `127.0.0.1`.
