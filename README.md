# AlemQuest

Платформа, которая помогает бизнесу превратить сырое описание проблемы в понятную практическую задачу, а студенческим командам — найти проект и предложить решение. MVP команды Juniors для HackAlem AI.

## Быстрый запуск

Нужен **Node.js 22.9 или новее** (проверено на 24.19). Сторонние npm-пакеты не нужны.

```sh
git clone https://github.com/BAITC-Hacks/hack-e38c07f2-juniors.git
cd hack-e38c07f2-juniors
node server.js
```

Откройте http://localhost:3000. При первом запуске автоматически создаётся `data/db.json` с синтетическими примерами. Изменения сохраняются после перезапуска. Сервер по умолчанию слушает только локальный компьютер.

Для AI скопируйте `.env.example` в `.env`, впишите собственный `OPENAI_API_KEY`, затем запустите:

```sh
node --env-file=.env server.js
```

Или используйте `npm start`, если npm доступен. Ключ остаётся на сервере; `.env` и локальные данные исключены из Git. По умолчанию настроена модель `gpt-4.1-mini`; её можно изменить через `OPENAI_MODEL`. Без ключа работает явно обозначенный локальный режим вопросов. Это резервная логика, а не вызов модели. Доступность модели и реальные ответы внешнего API требуют отдельной проверки с ключом команды.

## Реализовано

- Свободное описание задачи и 3–5 уточняющих вопросов.
- Перенос ответов в редактируемую карточку без добавления фактов.
- Подтверждение каждого поля человеком и отдельное подтверждение публикации.
- Прозрачный рейтинг 0–100 с расшифровкой, живым пересчётом и подсказками.
- Общий каталог, поиск, фильтры по отрасли и готовности, сортировка по рейтингу.
- Отклики: команда, идея, план, срок, ссылка на прототип.
- Ручной выбор или отклонение бизнесом; можно выбрать несколько команд.
- Подтверждение завершённого этапа: +10 баллов выбранной команде, однократно на отклик.
- Сохранение данных между перезапусками, серверная валидация, обработка ошибок.
- 5 исходных описаний, 5 карточек разной полноты, 5 профилей, 5 откликов.

## Сценарий

Бизнес открывает «Создать задачу», описывает проблему, получает вопросы, отвечает и переносит ответы в карточку. После проверки подтверждает поля и видит рост рейтинга. Подтверждает публикацию. Студенты открывают карточку из каталога и отправляют предложение. В кабинете бизнеса заказчик сравнивает отклики и вручную выбирает команду. После фактического завершения этапа заказчик подтверждает его, и баллы появляются в разделе команд.

Неопубликованный черновик виден в кабинете бизнеса. Опубликованная задача с уровнем «Черновик» видна всем и принимает отклики даже с нулевым рейтингом. Это разные понятия: статус публикации и уровень готовности.

## Формула рейтинга

`score = сумма весов заполненных и подтверждённых полей`.

Поле считается заполненным, если после удаления пробелов по краям содержит не менее 5 символов; требуется также явное подтверждение. Это проверка заполнения и самооценка бизнеса, **не автоматическая экспертиза достоверности или качества текста**. Рейтинг сервер пересчитывает самостоятельно и не принимает от клиента готовый балл. Изменение текста в интерфейсе снимает подтверждение поля.

| Показатель | Вес |
|---|---:|
| Контекст | 10 |
| Потребность | 10 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт | 5 |
| Формат взаимодействия | 5 |

Уровни: 0–39 — черновик, 40–69 — рабочая, 70–89 — готовая, 90–100 — приоритетная. В каталоге все опубликованные задачи сортируются по убыванию рейтинга; ограничения на отклик по рейтингу отсутствуют. Рекомендации и автоматическое назначение команд не реализованы.

## Технологии и архитектура

JavaScript, Node.js HTTP server, HTML/CSS и браузерные ES modules. Сборка и установка зависимостей не требуются. Данные хранятся в JSON; запись выполняется через временный файл и переименование.

```text
public/index.html + styles.css + app.js
                  │ HTTP JSON
               server.js
             /     |     \
   lib/domain.js   data/   OpenAI API (необязательно)
   рейтинг,        db.json уточняющие вопросы
   валидация
          lib/seed.js — синтетические данные
```

- `GET /api/state` — данные и серверные рейтинги.
- `POST /api/analyze` — уточняющие вопросы.
- `POST /api/tasks` — создание/редактирование/публикация.
- `POST /api/proposals` — отправка отклика.
- `POST /api/proposals/:id` — решение бизнеса или подтверждение этапа.

## AI и обработка некорректных ответов

Промпт и валидатор находятся в `lib/domain.js` (`aiPrompt`, `validateQuestions`). На вход передаётся описание и заполненные поля карточки. AI используется для анализа пробелов и вопросов; ответы пользователя переносятся в карточку буквально. Промпт запрещает добавлять факты и выбирать исполнителя.

Ожидаемый формат:

```json
{"questions":[
  {"field":"data","question":"Какие данные о продажах доступны команде?"},
  {"field":"success","question":"Какую точность прогноза вы сочтёте успешной?"},
  {"field":"constraints","question":"К какому сроку нужен первый прототип?"}
]}
```

Используется JSON mode Chat Completions и дополнительная серверная проверка: 3–5 вопросов, допустимые уникальные ключи, длина вопроса 10–800 символов. При таймауте (20 секунд), ошибке API, некорректном JSON или неправильной схеме включается локальная генерация вопросов, а пользователь видит причину перехода в резервный режим. [Документация OpenAI по JSON mode](https://developers.openai.com/api/docs/guides/structured-outputs).

## Проверка

```sh
node --test
```

Тесты проверяют границы уровней, начисление только за подтверждённые поля, отклонение некорректных AI-ответов и сквозной HTTP-сценарий: вопросы → публикация → отклик на задачу с нулевым рейтингом → ручной выбор → подтверждение этапа → повышение рейтинга → перезапуск и проверка сохранности данных. Повторное подтверждение этапа не умножает баллы. Используется отдельное временное хранилище.

## Данные и внешние сервисы

Все компании, контакты, задачи и профили в `lib/seed.js` синтетические; адреса используют домен `.example`. Ссылки на прототипы — демонстрационные `example.com`, а не реальные прототипы команд. OpenAI получает введённое описание при подключённом ключе. Google Fonts загружает Manrope для оформления; без доступа используется Arial.

## Ограничения MVP

- Нет регистрации, авторизации и разграничения доступа. Демонстрационный интерфейс позволяет переключать роли и работать со всеми задачами.
- Сервер рассчитан на локальную защиту одним процессом. Для публичного сервиса нужны авторизация, контроль доступа, лимиты запросов, резервное копирование и полноценная БД.
- Один подтверждаемый этап на отклик, без подробного проектного трекера и проверки фактического выполнения системой.
- Заполненность полей подтверждает человек; семантическая оценка качества не реализована.
- Не реализованы чат, уведомления, загрузка файлов, обучение модели и персональные рекомендации.
- Внешний AI нельзя считать проверенным до реального запроса с действующим ключом.
- Публичного развёртывания пока нет. Локальный адрес не является deployed-версией.
